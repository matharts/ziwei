# 跨语言 Conformance 用例

本目录保存语言无关、可追溯的排盘输入和预期事实，供 Rust、TypeScript 等实现分别验证。它是行为合同的机器可读辅助材料，不取代 [`domain-contract.md`](../docs/architecture/domain-contract.md)、[`CONTEXT.md`](../CONTEXT.md) 或已确认决策。

## 文件格式

- `schema/case.schema.json` 定义 case envelope；`cases/*.json` 每个文件保存一个稳定 `id`、合同版本、场景、输入、部分预期事实和依据。
- 输入使用领域身份拼写（例如 `Male`、`Jia`、`Zi`），不用 Rust 枚举序号、内存表示、宿主 DTO 或展示文本。
- Schema 检查结构和值域；用例执行器还须按领域合同检查组合约束，例如天干、地支必须组成阴阳匹配的六十甲子年柱。
- `expected` 可只断言该用例有独立依据的事实；未列字段不是空值，也不表示该能力不属于 V1。
- 可选 `queries` 以领域操作记录额外查询；case 表达查询对象与预期，不复用 Rust、TypeScript 或宿主 API 的方法名。
- `provenance.sources` 指向可定位的规则、固定规则手算或外部依据；`derivation` 说明如何从规则得到每个预期。引用实现源码仅可解释实现细节，不能作为预期依据。
- `evidence` 标出用例是否独立于被测实现推导、是否经过外部审定。现有手算例没有外部审定，不得升级表述。

用例验证器应在实现边界把领域身份显式映射到各自公开 API，再比较预期事实。不得调用生产数组生成预期身份，不得先运行 Rust 全量输出再把结果写回 case，也不得以双入口相同作为正确性证明。

## 当前覆盖

`natal.jia-zi-fire-six.1984-01-06` 与四个 `bureau-day-one-*.json` 用例基于已记录的手算材料，覆盖五种五行局、正月子时命身宫、来因宫，以及初一局数补数奇退偶进的紫微与天府定位。预期逐项手算并静态记录，不从 Rust 命盘输出提取；Rust 和 TypeScript 测试分别读取同一 case 文件并消费这些预期。

`ding-mao-reverse-periods.json` 与 `xin-you-forward-periods.json` 迁移两张固定手算命例：测试断言两种不同顺逆、局数与出生日补数的本命锚点、十二宫的地支／宫职／宫干／大限年龄区间、十八星全部落宫，以及第二大限和末流年的边界年龄／年份与命宫地支。其输入、宫位和星曜结果依据 `fixtures.rs` 中有注释的手算夹具，期间依据固定样例 README 与期间查询手算表。四化与自化标记尚未全部迁移。`reject-inconsistent-sexagenary-year.json` 记录甲丑参数输入；甲为阳干、丑为阴支，预期语义错误为 `INVALID_SEXAGENARY_YEAR`，并保留 stem/branch 身份。

| 五行局／初一补数 | 甲子火六与水二、木三、金四、土五四锚点 | 五局各一例，独立手算 |
| 手算命例 | 丁卯男、辛酉女 | 十二宫地支／宫职／宫干／年龄区间，十八星落宫，命身来因与紫微天府；期间首末边界 |

现有仓库还记录五种局数的三十日定位锚点，以及丁卯、辛酉例的完整星曜变换标记与十二项期间宫职数组，见[固定规则样例及推导](../crates/ziwei/tests/fixtures/README.md)。共享用例的四化／自化全集、其他期间组合与错误边界仍未迁移；不能据此声称共享 conformance 已覆盖完整 V1。

Rust conformance 测试通过 `include_str!` 读取仓库共享 case，并由 Cargo package 配置排除该测试文件，避免将不含共享 fixture 的测试代码打入独立 crate tarball。正常工作区测试仍执行这些 case。

## 维护要求

增加用例时先确认其规则仍有效，再人工推导预期并逐项写出来源。更改预期需说明规则修订、推导更正或源资料更正及其证据；不能为使某个实现通过而调整预期。外部审定状态必须有明确审定来源。

# 领域文档

## 依据与术语

探索领域或架构前，读取 [CONTEXT.md](../../CONTEXT.md)，并按主题读取 [V1 决策表](../architecture/v1-decision-map.md) 与 [Rust 包架构](../architecture/rust-package-design.md)。分别用它们核对领域术语与不变量、已确认的规格、模块职责与公开 API 边界。

若后续存在 `CONTEXT-MAP.md`，改按其指针读取相关上下文；有相关 ADR 时一并读取。可选文件缺失不阻塞工作，也不为补齐目录而创建文档。

- Issue、提案、假设和测试使用术语表中的词汇；缺失概念先判断是否属于现有模型，真实缺口留待领域建模确认。
- 标准或外部资料与项目规格分别核对；当前实现、历史实现和讨论示例都不能替代已确认的项目决策。
- 与已确认的决策或 ADR 冲突时，指出具体条目、冲突和理由，保留原约束直至用户确认变更。

## 领域变更

1. 只读核对当前实现、适用标准与已确认决策，定位差异。
2. 仅对尚未确认的领域语义或设计变更，提出边界明确的小决策并等待确认；已有决策且会话已授权实现时直接推进。用户明确要求等待“执行”时，按仓库的[任务边界](../../AGENTS.md#任务边界)处理。
3. 在确认与授权范围内实现一个垂直切片，用测试固定行为。规则、术语、历法转换或分析含义仍有缺口的部分保持未定。

新增或修改领域规则测试时，先读取 [固定规则样例](../../crates/ziwei/tests/fixtures/README.md)。预期值依据已确认规则独立推导并记录来源；两种入口的交叉验证仅作为一致性证据，不能替代独立预期值。

领域规则的表驱动测试覆盖已确认的正常、边界和无效输入；测试名使用术语表词汇，数据记录来源、适用流派与预期结果。未确认的语义不写入测试。验证覆盖本次行为与项目必需检查，通过后仅因新改动、失败或未解决疑点扩大或重复检查。
